# iqdb-persist v1.0.1

A fix release for write-ahead log recovery and snapshot loading. No API or
on-disk format changes; files written by 1.0.0 load as before.

## Fixed

- **Writes after a torn-tail recovery survive the next restart.** When a
  crash left a partial frame at the end of the log, recovery skipped it on
  replay but left its bytes in the file. New frames were appended behind it,
  and the next load stopped at the same spot, so every write acknowledged
  after the first recovery was lost on the second. `load` now cuts the log
  back to the end of the last intact frame and `fsync`s it before appending.
- **A failed append no longer poisons the log.** If writing a frame fails
  part-way (a full disk, an I/O error), the partial bytes are truncated away
  before the error is returned. If that truncation also fails, the log
  refuses further appends until it is reopened, rather than writing frames
  the next load could not reach.
- **Replay is idempotent.** A snapshot that already holds some of the logged
  mutations (after a WAL-mode `save()`, or a crash between a checkpoint's
  snapshot rename and its log reset) used to fail every load with
  `IndexBuild(Duplicate)`. Replay now skips an insert the index already holds
  and a delete of an id it no longer holds. The log only records mutations
  that applied cleanly, so this reaches the same final state however much of
  the log the snapshot covers.

## Security

- **Zstd decompression is bounded by its output.** Payloads are decoded as a
  stream and stopped one byte past the recorded length, so a small crafted
  file can no longer expand to gigabytes in memory before the length check.
- **LZ4 claims are bounded by what the format can produce.** A recorded
  length above 255 times the stored bytes is rejected before the block
  decoder reserves it; the previous bound was 4096 times.

## Upgrading

Change the version to `1.0.1`. Nothing else is needed.
